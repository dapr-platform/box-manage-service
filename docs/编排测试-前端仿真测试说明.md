# 编排测试（前端仿真测试）

对应方案：`ai_docs/编排测试方案-前端仿真测试.md`。本文档说明已落地的实现、用法与**已知差异**。

## 定位

**仿真负责「快」，真机负责「准」。** 前端仿真在浏览器内（Python 节点借助 Pyodide）逐帧运行编排，秒级得到每个节点的输入输出，用断言自动判断是否符合需求。结果**只作开发参考，发布以真机测试为准**。

测试范围：直接注入「推理结果」，验证的是**编排逻辑**（过滤、计数、状态切换、分支、消息内容），**不验证模型识别准确率**。

## 用法

1. 编辑器工具栏点「测试」打开右侧抽屉。
2. 「新建用例」手写，或「AI 生成用例」由业务需求生成（生成后需人工核对再保存）。
3. 勾选用例点「运行选中用例」。**仿真直接用当前画布数据，不需要先保存。**
4. 结果面板显示逐帧断言对比；选中某帧时，画布会高亮该帧实际执行的节点，失败节点标红（红色虚线）。

AI 快速编排在编辑已有编排时，会自动带上该编排的用例做**自动测试**：静态校验通过后跑一遍仿真，不通过则把失败信息回传给大模型进入下一轮修复（见方案第 5 节）。

## 用例格式

```json
{
  "name": "持续有人触发一次报警，人数增加再次报警，离开后解除",
  "description": "覆盖进入入侵状态、首次报警、人数增加重报、恢复正常四个阶段",
  "initial_context": {},
  "frames": [
    {
      "label": "有人 1~3 帧，未进入入侵状态",
      "repeat": 3,
      "inputs": { "detections": [{ "class_id": 0, "confidence": 0.92 }], "image_base64": "" },
      "expect": [
        { "path": "python_script-005.is_intrusion_detected", "op": "eq", "value": false },
        { "node": "wechat_work-007", "executed": false }
      ]
    }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `frames[].inputs` | 开始节点的输入变量（对应盒子端 `trigger_data.input_variables`） |
| `frames[].repeat` | 同样输入重复 N 帧；断言默认**只在最后一帧**判断 |
| `frames[].expect_each` | `true` 时每一帧都判断断言 |
| `frames[].mocks` | 仅仿真使用：为不能仿真的节点提供本帧输出，如 `{ "reasoning-003": { "detections": [] } }` |
| `expect[].path` | `<节点id>.<输出key>`，可用 `.` 访问嵌套字段 |
| `expect[].op` | `eq`、`ne`、`gt`、`gte`、`lt`、`lte`、`contains`、`exists`、`not_exists` |
| `expect[].node` + `executed` | 判断某节点本帧是否执行（验证条件分支） |
| `initial_context` | 第一帧之前的任务上下文 |

隐含断言：每一帧的执行必须成功，任何节点失败都直接判定该帧失败。

## 仿真支持范围

| 类别 | 节点 | 仿真方式 |
| --- | --- | --- |
| 完整仿真 | `start`、`end`、`condition`、`detection_filter`、`task_get_context`、`task_set_context`、`python_script`、`loop_start/end`、`concurrency_start/end` | 按 box-app 源码语义用 TypeScript 实现 |
| 只记录不发送 | `wechat_work`、`mqtt`、`http_request`、`rpa_wechat_proxy` | 完成 `{node.key}` 插值，输出 `{ dry_run: true, request: ... }` |
| 需要模拟输出 | `reasoning`、`reasoning_loop`、`face_compare`、`face_result_parser`、`image_annotator`、`kvm`、`script` | 读用例的 `frames[].mocks`；未提供时该用例标记为「仿真不支持」并跳过 |

遇到「仿真不支持且未提供 mocks」的节点时，**跳过自动测试并提示**，不会给出误导性的失败。

## 与 box-app 对齐的语义

正确性取决于下列语义与 box-app 完全一致。实现位于 `src/simulator/resolve.ts` 与 `nodes.ts`，每处都注明了对应的 box-app 函数。完整规格见 `ai_docs/box-app工作流节点执行语义规格.md`（1810 行，79 处源码引用）。

**高风险项**（`src/simulator/__tests__/resolve.spec.ts` 有对应用例）：

1. **布尔字符串不会被解析**：单变量真值判断中，字符串 `"false"` 与 `"0"` 都是**真**；只有裸 `true`/`false` 字面量才走布尔。`"true" == true` 为 `false`（JSON 深度相等）。
2. **`>=`/`<=`/`>`/`<` 在操作数非 number 时不立即返回 false**，而是继续走后续分支，最终落到单变量判断，实际结果为 `false`。
3. **`==` 用 JSON 深度相等**：两侧引用都解析失败时，`{a} == {b}` 为 **true**。
4. **`resolveInputs` 的回退顺序在两个分支里相反**：有 `ref_key_name` 时 `default` 优先于 `default_value`；无 ref 时是 `value > default_value > default`。
5. **Python 浮点入参用 `std::to_string(double)`**，即固定 6 位小数（`0.1` → `'0.100000'`），直接影响脚本里的字符串比较。
6. **`resolveReference` 的节点输出分支未命中时会继续回退查变量**（源码里该分支没有 return）。
7. **任意节点的 `output_data` 都有兜底填充**：inputs 解析值 + `_overrides` 非空值 + `config` 非 null 值，节点自身结果优先。断言 `node_outputs` 时最容易忽略。
8. **汇合节点没有 barrier**，多条入边的普通节点只执行一次；并发分支是**串行**执行的，且分支内忽略 `is_fork`/`is_loop_end`。
9. **循环回退不增加 steps**；`for`/`foreach` 的继续条件是 `current_index + 1 < total_count`。
10. **`task_get_context` 首次初始化用 `node.outputs` 的默认值**（`default_value` 优先），且**只要已有任意键就不再初始化**。
11. **失败即整帧中断**，失败路径不写 `end_time`/`duration`。

### 一个反直觉的真实行为（已照抄）

box-app 剥外层括号的循环**不做 trim**（`expr_copy = expression` 直接用原串比较首尾字符）。因此：

- `({a}||{b})&&{c}` → 括号被正确剥离，结果为 `true`
- `({a} || {b}) && {c}` → 按 `&&` 拆分后左侧是 `({a} || {b}) `（**带尾随空格**），首字符是 `(` 但尾字符是空格 → 不剥括号 → 整段被当作引用解析失败 → **`false`**

**只要括号组后面跟了空格，该括号组就失效。** 这是 box-app 的真实缺陷，仿真照抄以保证一致。

## Pyodide

- **本地托管**：约 13MB，通过 `pnpm run sync-pyodide` 从 `node_modules/pyodide` 复制到 `public/pyodide/`（该目录已加入 `.gitignore`），**不依赖外网 CDN**。`prebuild` 会自动执行同步。
- **Web Worker + 超时**：脚本在 Worker 中执行，超时时间与节点 `timeout_seconds` 一致（默认 30 秒）。优先用 `setInterruptBuffer` 中断；浏览器缺 `SharedArrayBuffer` 时降级为「标记超时并 terminate Worker 后重建」，避免死循环卡死页面。
- **标准库限制**：脚本导入 Pyodide 不具备的第三方库时该节点报错，请改用真机测试。

首次打开测试面板时才加载 Pyodide，之后浏览器缓存。

### AI 生成用例的原则

**用例从需求出发，而不是从编排出发。** 提示词只把节点与输出的**名称**告诉模型（用于拼断言路径），**不给脚本内容**——否则模型会照着实现写期望值，测试退化成「证明代码等于代码」。后端有单测锁定这一点（`TestBuildNodeOutlineOnlyExposesNamesNotScripts`）。

生成结果覆盖：正常触发前的过渡帧、恰好达到阈值的边界帧、阈值前一帧、中途漏检后恢复、触发后恢复、重复触发。

## 已知差异与限制

| 项 | 说明 |
| --- | --- |
| **`dry_run` / 演练模式** | box-app 源码中**完全未实现**（全仓 grep 无匹配）。`{dry_run: true, request: ...}` 契约来自设计文档，`request` 的具体结构无源码可对照。因此**真机测试上线前，仿真与真机的这四类节点输出结构可能不一致**。仿真在输出里额外带了 `msgtype`/`topic`/`published` 等字段便于断言。 |
| **`complex` 条件边** | `line_definitions` 表没有 `conditions` 字段，box-app 也从不加载它，真实运行时等价于**恒真分支**。仿真照抄该行为（有 `conditions` 时才逐条 AND）。 |
| **`detection_filter` 的 ROI** | box-app **没有**任何 ROI 逻辑与输出；`roi` 只出现在 `reasoning` 节点的 `roiConfigs` 透传。 |
| **`skip`/`skipped` 节点状态** | 不存在。条件未命中只是不遍历到该节点。 |
| **JSON 键顺序** | nlohmann 用 `std::map`（字典序），TS 保持插入序。断言与日志中出现键序差异属预期，不影响语义。 |
| **未逐行提取的节点** | `face_result_parser`、`face_compare`、`reasoning_loop` 未逐行提取语义，仿真一律要求提供 mocks。 |
| **不支持数组下标** | `resolveReference` 的 `a.b.0` 对数组无效（与 box-app 一致）。 |

## 如何扩展仿真器

1. 先在 `ai_docs/box-app工作流节点执行语义规格.md` 找到对应函数的精确语义（含行号）。
2. 在 `src/simulator/nodes.ts` 实现，**在注释里注明对应的 box-app 函数**。
3. 把它从 `MOCK_REQUIRED_TYPES` 移到 `FULLY_SIMULATED_TYPES`。
4. 在 `src/simulator/__tests__/` 补单测，**特别是边界情况**（空值、类型不符、缺字段）。

白名单原则：**只有能按源码语义完整仿真的节点才执行，其余必须提供 mocks 或走真机，不做「近似实现」。**
